## Corrections to the contract (found while writing this prompt — read before the pin matrix)

1. **The default-printing join is at `search/route.ts` 126**, not 111 (111 is `colorsMask`). `.leftJoin(cp, and(eq(cp.cardIdentityId, ci.id), eq(cp.isDefault, true)))`.
2. **"Rows carry `printingId`" is true in SQL and false on the wire.** It is selected at 121 (`printingId: cp.id`) and stripped by the mapper at 139–140 (`({ total: _total, printingId, imageOverride, cheapestUsd, ...card })`); `image` (144–146) is derived from it. To stay byte-identical, the wire gains `printingId` only when the request is scoped.
3. **Widening the shared `FieldTarget` breaks compilation.** `translate.ts` 120–123 (`"column" in field.target ? … : jsonbText(field.target.jsonbPath)`) and 150–153 (`const path = field.target.jsonbPath;`) narrow by `"column" in` alone. Either the `"set"` kind gets its own target type (not a `FieldTarget` variant), or those branches gain `"jsonbPath" in` guards. And the `switch (field.kind)` at 87 has no exhaustiveness check: forgetting `case "set"` compiles and silently ignores the parameter — add a `never` default.
4. **The translator returns no scope and knows no game.** `SearchTranslation` (48–53) is `{ conditions; rank; warnings }`, and the route's One Piece id pass builds that shape by hand (84), so a required `scope` field breaks it — make it optional. `translateSearch(fields, params)` (75–78) takes no game, so the `EXISTS` must correlate `sets.game_id = card_identities.game_id`; only `cardIdentities` is imported (20). Magic set codes are stored lowercase (`resolve-printings.ts` 10–11): lowercase the parameter.
5. **"An unknown code is an honest empty result with a warning" needs I/O the translator does not have.** The translator is pure ("malformed values produce warnings, never SQL", 8–9): it can refuse a malformed code, but a well-formed unknown one needs a lookup — a second statement, or a subquery whose emptiness the route reads. `/cards` is one statement per request today (two only with `format`, which `/cards` never sends); decide the count and record it with `DB_LOG=1`.
6. **`sort=number` does not exist, and nothing would send it.** The route's enum (55) lacks it, so today it answers 400. With no name, Magic's `/cards` sends no `sort` (`card-search.tsx` 139–140 → the route's default `pop`, 90–91). "A set and no name → collector number" needs the client to send `sort=number` or the route to default to it when scoped — and the in-set join must yield exactly ONE row per card, or `count(*) over ()` (123) and paging break.
7. **"With a name: relevance" is not what `/cards` does.** A typed name sends `sort=best` (`card-search.tsx` 139) — X2's `nameMatchOrder`, not the route's `relevance` (`similarity`). With a set AND a name, keep `sort=best`: the grid's order must stay the dropdown's order.
8. **D4's picker needs parts the primitive does not export, and it contradicts D0.** D4 draws a "[ Any set ▾ ]" trigger with the text box inside the popup, in two groups. The wrapper exports no `Trigger` and no `Collection` (`ui/autocomplete.tsx` 145–155) — Base UI 1.7.0 ships both (`@base-ui/react/autocomplete` parts include `Trigger`, `Collection`, `Clear`, `Separator`), and Base UI renders a grouped list only through `Group items={…}` + `Collection`. D0's rule "It opens at two typed characters and shows at most 8 rows" (WAVE3 190) does not fit a ▾ picker over 706 sets. Decide the picker's open rule and row cap; the popup's `min-w-72` (78) and anchor width still apply.
9. **The chip cannot name the set on landing.** D4 fetches the list "the first time the picker opens" (388) but draws "[ Set: Bloomburrow (BLB) × ]" — a visitor landing on `/cards?set=blb` has opened nothing. The name must come from somewhere: the search response, a mount-time `/api/sets` fetch only when `set` is preset, or a code-only chip. A fetch at every mount breaks `card-search.test.tsx` 84 (`expect(requests).toHaveLength(1)`). The owner's set header ("Eldritch Moon — the 71st expansion set") needs the same metadata, so decide one source for both.
10. **"Read once at load" holds, with two caveats.** `/cards/page.tsx` reads `searchParams` once per request and `CardSearch` seeds `useState` from them; but its `key` is `game` only (62), so a same-game client navigation to another `/cards?…` does not re-seed, and chosen filters never reach the URL.
11. **The rollback claim needs a gate that does not exist yet.** No `/cards` group is gated on the adapter's declaration today (Traits hangs off a page prop, `distinctField`; Color is hard-coded). X4a must render the Set group only when the game's adapter declares a `"set"` field, and read `set` for Magic only.
12. **Two date columns disagree.** `card_printings.released_at` is commented "Denorm from set" (`schema.ts` 187) but ingest writes the card's own date (`scryfall-map.ts` 339, `released_at: card.released_at ?? null`). "Released" is `sets.released_at` (WAVE3 A).
13. **The collector-number rule is stated two ways** — D4 390 "numeric first, then text"; the X4a risks line "leading integer first, then the full text, and numbers with no leading digit last". Pin the risks line's rule, and use the same expression for the per-card pick and the `number` sort.
14. **WAVE3 B's collector-number split does not sum**: 92,529 + 9,453 + 7,630 = 109,612 of 109,848. Measured 2026-09-28: 92,529 digits only · **9,689** digits then anything else (`^[0-9]+[^0-9]`) · 7,630 not starting with a digit = 109,848.
15. **The URL accepts what the picker hides.** Nothing stops `/cards?set=<an upcoming or digital code>`. Decide whether the scope requires a released paper set (the picker's list) or any known code.
16. **"Each link opens the card page on it" — after hydration.** The card page is ISR and never reads `searchParams`; `usePrintingParam` has a null server snapshot, so the server HTML shows the default printing and the gallery crossfades to `?printing=` once hydrated. Measured: 11 Bloomburrow basic-land printings sit at positions 101–113 of their card's printings (newest first) — past the 100 inlined rows, inside the API's 250 cap — so each costs the gallery one tail fetch (`printings-gallery.tsx` 242–249). None is past 250 (LATER row 88's fallback).

## Design decisions to make explicitly (disclose + pin each)

- **Where the kind lives**: a `"set"` `SearchFieldDef` with its own target type (recommended — no `FieldTarget` widening, no guards to add), the translator's `case "set"` emitting the bound `EXISTS` and returning an optional `scope`, and the `never` default in the switch.
- **The scope's statement count** and how an unknown code is reported (a `warnings` entry on the existing field is the additive slot; its words).
- **Which codes the scope accepts** (released paper sets only, or any known Magic code) — Correction 15.
- **The order**: a set and no name → `number` (client-sent or route default, decided); a set and a name → `sort=best`; the `number` rule's exact SQL, shared with the per-card pick.
- **The wire**: `printingId` only when scoped; the response names the set or not (the chip — Correction 9).
- **The picker**: its trigger (D4's ▾ button vs a text box), its open rule and row cap (D0 says two characters and 8 rows), its groups and row format ("Bloomburrow · BLB · 2024"), where the list comes from (`/api/sets`, fetched on first open), and whether picking re-runs the grid at once (it should — the grid is live on `/cards`).
- **`GET /api/sets`**: the row shape (`{ code, name, releasedAt, setType, group, cards }` per WAVE3), its order, `game=optcg` answering an empty list, and the cache header.
- **LATER row 124**: `/cards`' Name dropdown stays unscoped while a set scopes the grid (a pick is a "go to this card"), or it learns the set — decide and write it down.
- **The set view (the owner's answer)**: the header's words per line ("the 71st expansion set" for expansions; commander, masters, draft innovation alike; core sets and the added kinds — Eternal, bonus sheet, Secret Lair — labelled without an ordinal unless you decide otherwise and say why); where the ordinal is computed (in `loadReleasedSets`' SQL, one window per type with the same-day skip, so `/api/sets` rows carry it — the picker row can show it too: "Eldritch Moon · EMN · 2016 · 71st expansion"); **"Most played in {set}"** — 12 tiles by EDHREC rank (the search route's existing `pop` order, scoped, `limit=12`), hidden while a name is typed; then **"All N cards"** in collector-number order, paged at 60 as today.
