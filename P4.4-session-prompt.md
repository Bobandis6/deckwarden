## Design decisions to make explicitly (disclose + test-pin each)

- **Hub unit + slug shape.** Per leader CARD, not per name (17 Luffys = 17 archetypes). Extend assign-leader-slugs with a game_id-2 pass (or a sibling function) that inherits the append-only rule; pin shape + idempotence (run twice = 0 new) in tests.
- **Routing namespace** (LATER row 52's question, hub/queries.ts's "M4 revisits" note): /c/ stays MTG-only with a new OP root (/l/ or /op/leaders/…), vs /c/ opens cross-game. With external_key-suffixed slugs, cross-game collision is structurally dead — so pick on vocabulary and SEO grounds ("commander" is MTG-speak; OP players say "leader"), not collision fear. Hard constraint either way: MTG's 4,012 /c/ URLs do not move. Write the decision + reasoning into hub/queries.ts's header and the LATER row.
- **OP leader index**: where it lives (aligned with the routing decision), and its ordering with no popularity signal — name ASC + exact-color filter is the honest v1; external_key ordering interleaves EB/OP/P/PRB/ST prefixes alphabetically (poor "newest first" proxy).
