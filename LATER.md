# LATER.md — Deliberately Deferred

The scope-discipline file. Anything that threatens a milestone's package list lands here
with one line on when it earns its way back. Nothing on this list is a "no" — it's a
"not until the trigger fires." (See [deckwarden-build-plan.md](deckwarden-build-plan.md).)

| Full collection manager UI | Editor retention proven (post-M5). Schema exists from M1; ManaBox/Moxfield import + owned badges land in M3. |

| Smarter mana-source detection (P1.5's `producedMask` counts conditional producers like Command Tower as all five colors; fetches/treasure-makers not counted) plus analytics that consume role tags (curve targets, role-count vs hub-template comparison) | User feedback that the sources table misleads, or the first package that renders deck-vs-template analytics in the builder — P3.2's panel or P3.4 Cut Coach (which weighs roles by design). **P2.4 (2026-08-30) was the "first M2 analytics-adjacent session" and took the call: still deferred.** **P2.7 (2026-08-30) fired the tag-editing row** (chips + free entry in the card detail pane, preset chips reusing the adapter hub template's role labels — one editorial source of truth) — role *tagging* is done; what remains here is analyze.ts consuming those tags and the producedMask fix. **P3.1 (2026-08-31) — nominally "the next analytics-engine session" — took the call: still deferred.** Reasoning: the recommendation engine ranks *candidate* cards, which carry no role tags (tags live on deck_cards; no candidate-side role classifier exists), and its curve-fit signal reads cost buckets, not tags or produced mana — nothing in P3.1 consumes either item. These are analyze.ts/builder-panel features; the trigger above names their real home. **P3.2 (2026-08-31) took the call: still deferred — trigger now names P3.4 Cut Coach alone.** Reasoning: the Suggestions panel renders *per-candidate* evidence (why this card), not deck-vs-template analytics (how the deck compares to the shape); its curve evidence quotes the template per bucket but never renders a deck-wide comparison block. Cut Coach weighs roles across the whole deck by design — that's the real first consumer. |
| Co-occurrence as a recommendation ranking signal ("played together in N% of decks with your commander" — the plan's fourth signal, deliberately absent from P3.1's engine). Needs a real deck corpus to mine; deriving it from seeded or simulated decks is banned by the cold-start rule, and edhrec_rank is global popularity, not co-occurrence. When it lands: one more evidence source with its own honest name, same payload shape — the engine's RecommendMeta seam is built for it. | A deck corpus exists: Topdeck.gg ingestion (M3, tournament lists) or enough public community decks to mine honestly — whichever arrives first. |
| Markdown (or any formatting) in deck notes — P2.7 ships notes as plain text with pre-wrap line breaks | Users paste markdown primers or ask for headings/links. Rendering is the easy half; sanitization and a preview toggle are the real cost. |
| Real 403 status on private-deck/folder denial shells (they still serve HTTP 200). **P2.6 (2026-08-30) took the fired call: noindex the shells, keep 200 + the client gate.** Reasoning: (1) the crawler concern — the actual trigger — is fully answered by `robots noindex` metadata, which is also what Next itself injects on real 403s; (2) `forbidden()` requires the experimental `authInterrupts` flag on our pinned Next; (3) `forbidden.tsx` receives no props, so it can't render `PrivateShareGate` (needs deckId) — a real 403 would break anonymous claim-token owners viewing their own private deck at /d/…; (4) the data was never in the HTML. Status-code purity re-earns a look when authInterrupts goes stable AND the owner gate can move fully server-side. | authInterrupts stabilizes in a Next upgrade, or crawlers observed indexing the shells despite noindex. |
| setHint-aware import resolution + set codes in export (P1.6 resolves by name only, so two distinct cards sharing an exact printed name — Mystery Booster "Counters" — merge on import; the parser already captures `setHint`, the resolve route ignores it) | A real user hits it, or when One Piece import lands (M4) where set codes are the primary key anyway. |
| Single-deck DELETE (/api/decks/[id]) vs `forked_from_deck_id`: the self-FK has no ON DELETE, so deleting a deck that a live fork points at will 500 — unreachable today (nothing writes forks), and account deletion (P2.8) already detaches upstream pointers in its transaction. The fork feature owns single-deck delete semantics (null the pointer, like account delete does). | M3 forks package. |
| Dark mode default (§10 brand hook): globals.css carries full `.dark` tokens but nothing ever sets the class — the site ships light-only. Flipping the default (or honoring prefers-color-scheme) is a visual QA pass over editor/hubs/share/OG surfaces, not a toggle. Spotted during P2.8's home-page work; deliberately not smuggled into it. | A brand/design pass, or user feedback asking for it. |
| Spellbook popularity floor (≥ 1 or NULL) **stays** — P3.3 (2026-08-31) fired the scoped revisit and kept it. Reasoning: DB measured 204MB against the ~350MB free-tier alert line with Topdeck ingestion (P3.5) and collection import (P3.7) still to land; +38MB would buy detection only of combos EDHREC has seen in zero decks, and the Radar now **discloses** the bound in its panel footer ("covers combos with recorded play, plus unranked new ones") instead of implying completeness. Unranked (NULL) combos are kept and rendered honestly ("no tracked plays yet"). The row's other half — template-combo semantics — is settled and test-enforced (`deckComboStatus` in `src/lib/combos/view.ts`: a template combo is never "complete"; every surface renders "Also needs …", the engine's phrasing). Lifting the floor remains one constant in `spellbook-map.ts` + a re-ingest — fully recoverable. | Neon paid tier / VPS move (the 38MB stops mattering), or a user reports a real combo the Radar misses that Spellbook lists at zero popularity. |
| `artist` column on `card_printings` (~1.5MB). P2.6's OG images render art_crop + the required artist/© line by fetching artist from the Scryfall API at render time (data-cached daily per printing, og/scryfall.ts) — chosen over a migration because adding the field means touching the hash-guarded ingest the same week its spellbook step first runs unattended, plus a full backfill run. A stored artist would drop the OG path's runtime Scryfall-API dependency. | OG unfurl latency measurably hurts, Scryfall asks us to cut API traffic, or M4's image-mirroring work touches ingest anyway (punk-records carries artist too). |
| OG share images for folders (/f) and profiles (/u) — P2.6 shipped the plan-scoped three (decks/hubs/cards); folders/profiles unfurl with site defaults. | Folder-link sharing shows real usage, or the Deck Passport polish item gets picked up. |
