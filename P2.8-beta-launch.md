## The three hardening calls (recorded)

1. **Auth rate limiting — shipped.** Better Auth's limiter enabled with a
   `customStorage` backend over the existing `rate_limit_counters` table
   (fail-open, `auth:` key prefix, nightly sweep) — serverless-correct with
   no second table and no new write pattern. Stock rules: 100/10s per
   ip+path, 3/10s on `/sign-in/*`. SSR `getSession` calls bypass the
   limiter (router-level only), so the write cost is per client auth call.
2. **Account deletion — shipped.** Danger zone on /account → type-to-confirm
   → `DELETE /api/account` (session + confirm-literal body), one transaction:
   likes recount, fork-pointer detach, decks delete, user delete (cascades
   the rest). Decks are **deleted, not orphaned** — an orphan (no owner, no
   claim token) is uneditable forever and the anon purge reaps it in ≤12
   months anyway, and "delete my account" should mean the decks. GitHub-issue
   routing **stays, demoted to fallback** on the privacy page for people who
   can no longer sign in. Covered by `pnpm smoke:account`.
3. **`accounts` in the backup — shipped.** Nightly backup now COPYs the
   identity columns (issuer, account_id, provider_id, user_id) to a
   same-stamp CSV, like the identity map — OAuth tokens deliberately never
   land in R2. The restore drill loads the CSV and fails if any restored
   user would be left without a sign-in link.
