## Design decisions to make explicitly (disclose + test-pin each)

1. **Overlay file format** (`data/optcg/legalities.json` — the AUTHORITY, plan
   §"hand-maintained overlay because community scrapers lag Bandai"): suggest
   `{format:"standard", source_url, retrieved, entries:[{cardId /*external_key*/,
   status, effectiveFrom, condition?, note?}]}` — external_key keys (hand-editable,
   portable), the applier resolves to identity uuids. Decide and freeze.
2. **The applier**: a pure diff (overlay vs current non-scryfall rows for format 2)
   + close/open dated rows, the scryfall.ts:387–410 differ pattern, source
   'bandai:<effectiveFrom>'. Where it runs: end of scripts/ingest/punk-records.ts
   (even on sha-skip nights? the overlay can change without an upstream commit —
   lean: run the applier UNCONDITIONALLY before the skip check exits, it's one
   file vs a handful of rows) or its own tiny step. Decide; either way the nightly
   applies overlay edits within a day and `pnpm` has a manual entry point.
3. **validate() rule set + codes**: DECK_SIZE (50 exactly, leader excluded),
   LEADER_REQUIRED / LEADER_ZONE (exactly 1, category leader, main deck may not
   contain Leader-category cards), COPY_LIMIT (4 per identity), COLOR_IDENTITY
   (reuse the code — the message says "outside your Leader's colors"), BANNED,
   BANNED_PAIR (conditional row whose leaderIds hit the deck's leader). Decide
   error-vs-warning per rule (MTG pattern: previews warn — OP has no previews, all
   errors except maybe size-under while building — check how the editor surfaces
   mid-build states for MTG and match).
4. **banned_with_leader leaderIds vocabulary**: external_keys in the overlay AND in
   the stored condition jsonb (readable, stable across dump/restore), adapter
   resolves against the deck's leader CardData — needs the leader's external_key on
   CardData... it is NOT in the wire today (resolve strips it). Decide: add
   external_key to CardData/wire (small, game-agnostic, useful) or store leader
   identity uuids in conditions (opaque but zero wire change). Lean: put
   externalKey on CardData — import/export and future OP work all want it.
5. **Smoke** (`smoke:optcg` extension or `smoke:optcg-deck`): create ONE anonymous
   OP deck via API, PUT a decklist exercising every rule (a banned card if one
   exists, a 5th copy, an off-color card, 49 cards), assert issue codes, DELETE.
   **Prod deck-create budget is 10/h + 30/day per IP (fixed windows :00 UTC)** —
   read rate_limit_counters before a prod run; one deck total, delete it.
