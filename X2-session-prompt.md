## Design decisions to make explicitly (disclose + pin each)

- **The order.** Prefix-first (the contract's default) or any matching word, most played first. Ask the owner at the start; ship the default without an answer.
- **Hover and Enter.** Keep `highlightItemOnHover`, or turn it off so that D0's "nothing is highlighted until an arrow key is pressed" is literally true.
- **What a pick leaves in the box.** On `/commanders` and `/leaders` the page is about to change. On `/cards` the box is `q`: decide whether a pick may rewrite it and re-run the grid on the way out.
- **The footer row** on `/commanders` and `/leaders` ("Show every commander matching “atr” ↵"): a row that submits the form, as D2 draws it. `/cards` has none — its grid is already live.
- **Where class 4 applies.** The filter and the grid accept a match inside a word, ranked last; the dropdown does not. Keep the three callers on one module with one switch.
- **Class 5's trigger**: fewer than 8 rows found and at least 4 characters typed.
- **`sort=best` in the search route.** The default path must not change by a byte. Decide how the route gets the rank-class expression without touching what `translateSearch` returns today.
- **The hub filter's order and pages.** `/commanders` pages by 60, most played first. With the shared matcher the order is class, then play. Say what page 2 of a filtered list is.
- **One Piece rows**: leaders first, then name, then card number; the card number in the row; the thumbnail slot is a spacer while `thumbnailUrl()` returns null.
- **A row's quiet detail**: color chips for a leader, the type line for a card, the card number for One Piece.
- **The empty answer.** Fewer than two characters is a 200 with no rows and no query. Decide whether it carries the cache header too.
- **Popup width on a phone**: as wide as the input, never under 18 rem. Check 390.
